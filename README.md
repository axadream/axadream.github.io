# alepax.com

Personal site of Alex Pintea: AI engineering, Blender, Three.js.

## Preview

```sh
python -m http.server 8080
```

Then open http://localhost:8080/

## Hero graph buttons

- "Play the graph" loads the 3D scene on first click and turns into "Running" (pressed).
- "Reload" appears while running and rebuilds the scene on a fresh canvas. If the
  rebuild fails, the button returns to "Play the graph" and the label shows an error.

## Debugging motion

- Add `?motion=force` on localhost or 127.0.0.1 to run the hero graph even when
  prefers-reduced-motion is set. Ignored on any other host. `?motion=reduce` on the
  same hosts forces the reduced-motion path for testing.
- With reduced motion the graph stays still after Play and `#graph-label` says so; drag still works.
- The same override exposes `window.__graph` with `positions()`, `energy()` and `fps()`.
  It is removed when the scene is disposed.
- Ambient float amplitude, period range and depth wobble are the `AMBIENT_*` constants
  in the `K` block of `graph-scene.js`.

## Structure

- `index.html` - the landing page
- `about/index.html` - the /about/ page, generated by `scripts/build-log.mjs` from `content/about.md`
- `content/about.md` - source text and `jobTitle` for /about/ and the home JSON-LD
- `assets/css/site.css` - styles
- `assets/js/site.js` - main script
- `assets/js/graph-scene.js` - lazy-loaded Three.js chunk for the hero graph
- `assets/js/graph-layout.js` - pure layout functions shared by the SVG poster and the scene
- `data/nodes.json` - nodes of the hero site graph, see below; `site.config.json` sets `graph.maxNodes`
- `vendor/three.module.min.js` - Three.js, pinned to 0.170.0
- `assets/img/` - images and icons
- `archive/` - legacy pages, marked noindex and disallowed in `robots.txt`
- `scripts/check-no-business.mjs` - repository guard (see below)

## nodes.json

One object per node: `id`, `type` (`project` or `log`), `label`, `url`.

- Project: `status` is `released` or `planned`. A released project has `updated` (ISO date, replaces `date`); a planned project has no date and renders as a dim hollow ring labelled `(planned)`. Optional `title` is the short name shown in the graph label.
- Log: `date` (ISO). The label's text before ` - ` is the short name.
- `Last update` counts log dates and released projects' `updated` only; node colour tiers (new <= 7 days, recent <= 30, older) follow the same dates.
- Motion constants live in the `K` block at the top of `graph-scene.js`. Node positions are never stored.

## Posting a log entry

Use the CMS at https://alepax.com/admin/ (on localhost, `/admin/` of the local server):

1. Choose **Sign In Using Access Token** and paste a token (see below).
2. Open the **Log** collection and click **New Log**.
3. Fields: **Timestamp**, **Made**, **Track** and **Text** are required. **Text** is plain
   text, at most 300 characters, no Markdown. **Cards** are handbook IDs like `L1-001`.
   **Proof** must start with `https://github.com/axadream/` or `https://alepax.com/`.
   Posts with Made **AI-guided** or **Mixed** must have a Proof URL, or the guard fails.
   **Manual** Proof is optional. **Prompt trace** is Markdown, at most 1500 characters. **Minutes** is 1-600.
   **Draft** entries are skipped by the build.
4. Made: **AI-guided** is code the AI wrote from your spec. **Manual** is every line typed
   by you. **Mixed** is anything in between. Track: **App**, **AI Study**, **Math** or **3D**.
5. The CMS saves `content/log/<YYYYMMDDTHHMMSSZ>-<slug>.md`. The slug is the first
   40 characters of the text.

By hand, add `content/log/<YYYYMMDDTHHMMSSZ>-<slug>.md`:

```markdown
---
ts: 2026-11-12T20:00:00+01:00
made: Manual
track: Math
minutes: 45
---
Short plain-text summary, at most 300 characters.
```

Then run `node scripts/build-log.mjs`, review the diff, and commit.

## Access token

1. GitHub -> Settings -> Developer settings -> Fine-grained tokens -> Generate new token.
2. Resource owner: `axadream`. Repository access: **Only select repositories** -> `axadream.github.io`.
3. Permissions: **Contents** -> Read and write. Metadata read is added automatically.
4. Expiration: 90 days.
5. Store the token in a password manager. Never commit it or paste it into a log or screenshot.
6. To revoke: the same token page -> the token -> Delete. If a token ever appears in a
   log, a screenshot or a commit, revoke it at once.

## Logging from Claude Code (skill `log-post`)

The skill `log-post` (in `tools/log-post/`) writes a practice log entry from a Claude Code
session. It shows a preview, waits for an explicit yes, then creates the entry under
`content/log/` on `main` through the GitHub Contents API. Posting the same entry twice does
nothing. If the network is unavailable, the entry is kept in a pending queue; run `--flush`
to send it later.

Install (from the repository root):

```powershell
powershell -ExecutionPolicy Bypass -File tools/log-post/install.ps1
```

The installer copies the skill to `~/.claude/skills/log-post` and creates the config folder
`~/.alepax-log/` outside any repository, with two files:

- `allowed-projects.txt`: absolute project paths, one per line. The script refuses to run from anywhere else.
- `deny-terms.txt`: one term per line, case-insensitive. Entries whose text or link contain a term are refused.

Token: set the environment variable `ALEPAX_LOG_TOKEN` to the same fine-grained token as in
the [Access token](#access-token) section. Never write it into a file.

Use `--dry` for a preview without any network call.

The skill keeps its own copy of the schema (`tools/log-post/log-entry.schema.json`). It must
stay equal to `schema/`; a test enforces this.

## Reserved sections

## Guard

Run before every commit:

```sh
node scripts/check-no-business.mjs
```

It fails on commercial and advertising terms, and on the reserved sub-project
segment in any shipped path. It also enforces the per-page budget: first-party gzipped JS <= 12,288 B, and no chunk may load without a user action.
`index.html` must not reference `graph-scene.js` or `three.module`; `assets/js/site.js` may reference them only on a line carrying the `/* user-action-load */` marker.
Stale generated outputs (the `index.html` log region, `log/index.html`, `data/nodes.json`)
only WARN by default, because markdown-only post commits may leave them stale; CI rebuilds them.
The exit code is unchanged. `--strict` makes stale outputs FAIL (exit 1).
Code changes must run `node scripts/build-log.mjs`, then `node scripts/check-no-business.mjs --strict`, before commit.

### Tests

- `node --test` runs the `node:test` suite in `tests/*.test.mjs`. The workflow runs it too.
- `node tests/graph-regression.mjs` is a Playwright run and is not part of the deployed site.
- It resolves Playwright from `import('playwright')` or the npx cache. First run once:
  `npx --yes playwright@1.48.2 install chromium`.
- It falls back to an installed Chrome or Edge when no bundled browser is found.

## Sharing images

- Regenerate the four share images with one command: `node scripts/make-og.mjs`.
- It writes `assets/img/og-home.png`, `og-about.png`, `og-log.png` and `og-work.png`, each <= 60 KB. JPEG (q80) is used only as a fallback when a PNG is too large.
- Page titles live in the script's page list (`PAGES`).
- Pages reference the images through the shared meta helper `metaTags` in `scripts/build-log.mjs`.
- It needs Playwright, resolved the same way as `tests/graph-regression.mjs`.
- Image URLs carry `?v=<version>` so crawlers refetch after a release (generated from `site.config.json`).
- `/feed.xml` is generated by `node scripts/build-log.mjs`.

## Deploy

- GitHub Pages user site, published from branch `main`.
- `CNAME` holds the custom domain and must stay.
- `.nojekyll` disables Jekyll processing.
- OpenHorizon is a separate repository, served at `/OpenHorizon/` by GitHub Pages.
  Nothing with that name may be added to this repository.
- To publish, merge `v1-site` into `main`.
- The `lighthouse` job runs after `build` on the staged site, using @lhci/cli (dev-only, pinned). It checks `/`, `/about/` and `/log/` against the thresholds (performance >= 0.90, accessibility = 1, best-practices >= 0.95, seo = 1, home page <= 150 KB before any click). Deploy waits for it, so a failing assertion blocks the release.
- HTML reports are in the workflow run's Artifacts as `lighthouse-reports`. Thresholds live in `.lighthouserc.json`.
- `.lighthouserc.json` is the single source of the 150 KB limit.
- If a first run fails in an unexpected way, revert the merge in one PR.

### Deploy: switching Pages to GitHub Actions

1. Merge to `main`.
2. Repo Settings -> Pages -> Build and deployment -> Source: **GitHub Actions**.
3. Actions tab -> **pages** workflow -> **Run workflow** (branch `main`).
4. Verify https://alepax.com, https://alepax.com/log/ and https://alepax.com/admin/.

Rollback: Settings -> Pages -> Source: **Deploy from a branch** -> `main` / `(root)`.
This redeploys the committed files within minutes. The workflow can stay enabled.

The CMS Content Security Policy is the `<meta http-equiv="Content-Security-Policy">`
line in `admin/index.html`. If the CMS misbehaves after sign-in, first check the
browser console for CSP blocks.

## Versioning

- The version lives in `site.config.json` (`version`), mirrored in the footer `.foot-ver` line of `index.html` and in `CHANGELOG.md`. The footer reads "© <year> Alex Pintea · v<version>"; `build-log` computes the year from the newest log entry timestamp, so it never needs hand-editing.
- `scripts/check-no-business.mjs` fails if the three disagree, or if `threeDWork` or `lab` is not `false`.
- Release: bump all three, run the guard, commit, then tag `v<version>`.
